## 实际环境与安装影响

- Ubuntu 24.04.5 LTS，Linux `7.0.0-1013-oracle x86_64`。
- 2 个可见 vCPU，MemTotal `974968 KiB`（约 952.1MiB）；按一核配额执行，没有把可见 CPU 数当成购买套餐保证。

- systemd 255、cgroup v2、iproute2 6.1.0、nftables 1.0.9、util-linux 2.39.3、Python 3.12.3，TUN 存在。
- `/run` 为 tmpfs，挂载含 `nosuid,nodev,noexec`；这一安全策略保留原样。
- 本轮只新增 `openvpn 2.6.19-0ubuntu0.24.04.4` 和 `libpkcs11-helper1t64 1.29.0-2.1build2`，没有升级/删除其他软件包或安装推荐的 DKMS 模块。
- 安装期间使用临时服务启动保护并禁止自动重启既有服务；保护文件在结束时移除。新包的 OpenVPN 通用系统服务保持 **inactive / disabled**。

安装前后检查原有监听 PID 仍存在。下面的严格网络/进程快照基线始于安装完成后的首组实验，不将它冒充完整的软件安装前后文件系统审计。

## 首次失败与修复

初次 IPC 输出明确的 `fork/exec /run/...: permission denied`，3 项失败、仅旧 socket 归属用例通过，不能算 IPC 验收成功。随后只读检查确认：umask 为 0022、测试根目录 0755、LSM 标签 unconfined，而 `/run` 文件系统为 **noexec**。命名空间、进程及运行记录已清理，宿主快照没有变化。

修正没有重新挂载 `/run`，没有让普通用户获得 root，也没有删除失败断言：

1. 新增仅供 Linux 集成测试使用的 `internal/labexec`，生产二进制依赖树不包含此包。
2. 把测试程序副本移到显式固定的 `/usr/local/lib/miku-gate-lab-exec`；运行时数据仍在 `/run`。
3. 校验 root 所有的可信祖先和可执行文件系统；对任意目录、符号链接、不安全权限和 noexec 明确拒绝。
4. 文件完整写入后设为 0555，并关闭写描述符；专属随机子目录设为 0755，普通测试 UID 只能读/执行。
5. 清理只处理记录的同一 inode 和空目录，拒绝替换对象或多重硬链接；不递归删除。
6. 用修正后的干净提交重新构建、上传到新目录、核对哈希，并重跑全部三组；首次失败和旧产物保留。

这修复的是测试夹具的文件系统兼容性，**不是完成了生产 worker 权限分离**。

## 三组结果与资源

每组均在独立 systemd scope 中执行，实际读回：`cpu.max=100000 100000`、`memory.max=402653184`、`memory.swap.max=0`、`pids.max=64`。Go 使用 `GOMAXPROCS=1`、`GOMEMLIMIT=192MiB`；后者是 GC 软目标，不是硬上限。

| 组别 | 实际通过项 | 测试进程墙钟时间 | cgroup memory.peak | 退出码 |
| --- | --- | --- | --- | --- |
| netexec | 7 项主测试 + 6 个文件对象子用例 | 5.179s | 13,987,840 bytes（13.34MiB） | 0 |
| IPC | 4 项主测试，含真实跨 UID HTTP 链路 | 1.894s | 166,019,072 bytes（158.33MiB） | 0 |
| OpenVPN | 1 条完整受控隧道/断线旅程 | 4.385s | 27,615,232 bytes（26.34MiB） | 0 |

三组都不是 SKIP；所有内存压力/OOM 和任务配额拒绝增量为 0；结束时 scope 中没有子进程。

**这些数字不是网关常驻内存或容量承诺。** `memory.peak` 包含本组 Python 守护、Go 测试、子进程、内核及相关缓存记账；文件缓存的计费归属会影响它。辅助 `RUSAGE_CHILDREN` 最大 RSS 分别为 23,132 / 146,004 / 25,308 KiB，既不等于 scope 峰值，也不能相加成为总内存。这次没有进行并发吞吐或长稳负载测试。

### 内核与 IPC 的实际断言

- IPv4/IPv6 正向对照确有连通能力，然后验证默认丢弃、进/出方向阻断及 nft 丢包计数。
- 拒绝被替换 namespace、额外接口、活跃进程情况下的清理；不误杀进程，已知准备失败可以回滚。
- 重启锁与共享检查正确，FIFO/符号链接/目录/硬链接/宽权限/畸形记录均被拒绝。
- 指定 UID 65534 可以创建、读取和清理真实沙箱；同组错误 UID 与 root 客户端被拒绝。
- 客户端在发送请求前拒绝非 root 伪服务器，即使 socket 路径被改成 root 所有。
- 真实普通用户 HTTP 控制面经过认证、CSRF、确认、IPC 到 root 内核执行器；删除互锁生效，**VPN start 仍返回 409**。

### OpenVPN 正反对照

正确身份完成真实 mTLS 握手与 TUN 建立；错误服务器名必须产生明确名称校验失败，不能用泛化网络失败冒充通过。服务端推送的路由/DNS未改宿主；UDP DNS、截断后的 TCP DNS 和业务 TCP 均通过隧道，服务观察到 TUN 来源。私网/混合 DNS 答案拒绝，DNS 超时不回落宿主。

主动终止客户端 OpenVPN 后，已建立连接与新连接均被阻止。实验还故意在客户端私有 namespace 中放置底层默认路由，使用测试专属未绑定 socket 尝试绕行；内核计数增加，服务端连接/消息不增加：

| 指标 | 断线前 | 断线及绕行尝试后 |
| --- | --- | --- |
| 客户端默认丢弃计数 | 2 | 7 |
| DNS UDP 请求 | 6 | 6 |
| DNS TCP 请求 | 1 | 1 |
| 业务 TCP 连接 | 5 | 5 |
| 成功业务消息 | 5 | 5 |
| 非 TUN 来源请求 | 0 | 0 |

此表是本次 VPS 的观测，不照搬临时 runner 的绝对计数；它证明这条受控路径的正反对照，不证明所有故障和恶意 root 情况。

## 宿主与最终残留检查

三组和最终复核使用同一规范化快照哈希：`76a6c7ec51eed09825b856e794e000b7745c361ca6994de726b9b824747b4fc0`。新增的挂载观测字段单独保留；与第一次旧版实验基线共有的网络/服务字段也逐项相等。

最终确认：

- 接口、IPv4/IPv6 路由与策略规则、nftables、DNS 文件哈希、转发/IPv6开关、监听端点及原有 **11 个监听进程的 PID 起始身份**一致。
- `/run` noexec 保留，实验进程、systemd scope、命名空间注册项均为零。
- 临时安装保护文件不存在，dpkg 无待修复状态，OpenVPN系统服务 inactive/disabled。
- 所有已知测试运行根和可执行根不存在或为空，没有新的 Miku 公网监听。

**有意保留，不声称“整机零改动”：** 两个新软件包及其标准配置目录；两个 root 私有产物目录（旧版 36,952 KiB、新版 37,004 KiB，合计约 72.22MiB）；`/usr/local/lib/miku-gate-lab-exec` 和部分 `/run` 空测试根、空 `/run/netns` 注册目录。已删除的是本轮持有归属的临时程序副本、数据库、socket 和 namespace，不是历史证据。
