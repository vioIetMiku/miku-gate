# 已有入口识别与定向路由候选（dev.9）

## 管理界面

登录 → 系统与诊断 → 已有入口配置。选择固定来源，明确勾选读取同意，才能读取入口摘要。返回：配置 SHA256、匿名入口 ID、标签、协议、配置监听地址/端口、传输、安全类型、客户端数量和 Vision 标记。不会回显客户端 UUID、密码、私钥、原始 JSON，也不会单独打开证书私钥文件。标签来自原配置，用户应避免把凭据当标签。

源 ID 固定为 `x-ui`、`xray-local`、`xray-etc`、`sing-box`；对应常见路径可由 `miku-gate ingress sources` 查看。普通服务账号不能读取 root 私有配置时返回明确错误，不 chmod 放权，也不自动接管。后续安装助手需要在本机授权身份读取并传回安全摘要；本阶段没有任意路径文件读取 API。

## 命令与候选

`miku-gate ingress inspect --source=x-ui --confirm-read` 只输出摘要。Linux 上固定路径按目录 FD 逐级读取，拒绝符号链接、非 root 所有/可由组或其他用户改写的配置路径、非普通文件、硬链接和超过 1MiB 的配置。只支持严格 JSON；重复键、注释/JSONC、尾随值、过深/过多令牌均拒绝，不把含凭据的解析错误片段写入日志。

`miku-gate ingress prepare` 接受固定来源、确认读取、入口 ID、此前配置摘要及新私有候选路径；还需要 `--confirm-create`。认证材料仅通过 stdin 的小型 JSON 传递：`port`、`username`、`password`，不把密码放在命令参数。候选输出父目录须为当前用户所有0700，新文件0600、O_EXCL，并通过dirfd创建，拒绝覆盖或符号链接。

此命令是本机管理员工具，不是浏览器输出完整配置的 API。候选文件包含原有客户端/密钥字段和新的 Miku 本机代理认证材料，必须保密；输出的 Plan 只有摘要/标签/固定127.0.0.1目标/端口，**不包含完整 JSON 或代理密码**。

## 保留与定向路由

- 支持有唯一标签、明确配置端口/数字监听地址、有客户端的 VLESS/VMess/Trojan/Shadowsocks TCP类候选。非法/未知传输、缺标签、重复标签、detour等保持不可选。候选只是结构兼容，不证明配置本身有效。
- 原有 inbounds/客户端/TLS/REALITY 字段保持不变，原有 outbounds 和规则保持顺序及内容。仅为选定入口添加最前面的 UDP 阻断规则与 TCP → 认证 SOCKS5 规则。
- Xray 新增 SOCKS outbound + blackhole；sing-box 使用现代 action route/reject。全局 domainStrategy、默认出口和其他入口不改。存在 Miku 标记路由时拒绝重复叠加，需要后续专门更新。
- 本机 SOCKS 地址固定127.0.0.1，不能借候选工具生成任意外部代理目标；业务域名交给 Miku 前端处理，不给旧直连后备。
- 路由配置候选不是 DNS/内核保护证明，真实核心校验/数据实验必须另外完成。

## 面板生成文件的特别限制

x-ui/3x-ui 的 `bin/config.json` 是生成物，面板可能在重启/改节点时覆盖。**不能把改这个文件当成已完成持久复用。** 后续要接面板的持久化路由设置并处理备份/恢复，或让用户选择并行新建/明确迁移；本阶段不读取/修改面板数据库，不重启 x-ui/Xray，不宣称已复用。

## 真实核心实验入口

手动 `Existing encrypted ingress core lab` 以固定官方 Xray v26.3.27、sing-box v1.14.3 压缩包 SHA256下载，核心不安装到用户 VPS。隔离空间只有 loopback，普通 UID运行核心和测试。用私有 CA 的 TLS+Vision/VLESS双入口证明：候选真实 check、选定 TCP → Miku 认证 SOCKS、域名不由宿主解析、未选入口维持原路径、选定 UDP 阻断与未选 UDP正向对照、Miku停止后不回旧直连。测试新增不代表已实际通过；精确结果另记验收。

仍待：配置实际端口/PID归属和核心版本、管理端授权助手、UI持久绑定、核心check的生产封装、备份/应用/回滚、面板持久化、域名/IP HTTPS和安装脚本。不能把候选生成与实验通过当作完整复用交付。
