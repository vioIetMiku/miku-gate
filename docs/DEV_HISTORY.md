# Miku · fanout 版

直接基于 byJoey/fanout 的单页节点搭建工具。版本：0.2.0-dev.34。

## 安装

把 `miku-fanout-vps-dev34.tar.gz` 上传到 VPS，然后运行：

```bash
sudo tar --no-same-owner -xzf miku-fanout-vps-dev34.tar.gz
sudo bash miku-fanout/install.sh
```

如果下载的是 `miku-fanout-dev34.zip`，解压后进入其中的 `miku-fanout` 目录，运行 `sudo bash install.sh` 即可，已包含两种架构的程序。

支持 amd64 / arm64 的 Linux VPS，支持 systemd / OpenRC；VPS 必须提供 TUN。
安装器先检测并补齐 Python、OpenVPN、curl、OpenSSL、iptables、iproute 和 CA。
程序已编译，VPS 不需要安装 Go。两种核心自动准备，复用旧 Miku 登记的核心或按固定 SHA256 下载官方版本。
端口占用时自动选择空闲端口。安装结束打印管理地址、访问口令，输入 `miku` 呼出菜单。网页右上角可管理域名与证书，旧版可直接执行新版安装脚本或 `miku update`。
管理端口、入口端口和公网代理端口需在服务商安全组放行。

无域名默认 `http://VPS_IP:端口/随机路径/`；有域名可在安装结束时选择绑定，也可之后运行 `miku domain`。
新域名先设置 A 记录指向 VPS；自动签证书需要能访问 80 端口，也支持复用 Certbot 的已有证书。
域名可更换或用 `none` 解绑。REALITY 使用自己的握手目标，不需要管理域名证书。

## 怎么搭节点

1. 页面前面先看入口。自动检测 3x-ui、S-UI、xray-cf-lite；没有面板就使用自建 Xray。
2. 点“添加出口”，选国家、数量和入口模板。没有模板可选“自动创建 VLESS REALITY 入口”。
3. 自动从 VPN Gate 获取 OpenVPN 配置、建隧道、分配空闲端口、复制入口并绑定落地。
4. 连通后直接点复制节点；也可以复制认证 SOCKS5 / HTTP 地址，或拿订阅地址。

保持 fanout 的批量按国家建出口、每国批量、换线、重连、自动补位、客户端添加/重置/删除、凭据修改、节点导出和订阅。
换线保留端口、代理凭据、UUID 和链接。SOCKS5 / HTTP 共用一个认证端口，HTTP 支持 CONNECT。
设置中可选择自建 Xray 或 sing-box。XHTTP 使用 Xray；切换核心会校验配置。
自建核心可以给同一个入口中的不同客户端选择不同落地，用一个监听端口提供多个国家的链接。
面板模式仍按 fanout 方式复制入口，每个落地一个端口。

## miku 菜单

```bash
miku                 # 快捷菜单
miku info            # 管理地址和当前口令
miku password        # 忘记密码时直接修改，无需旧口令
miku domain          # 随时绑定 / 更换 / 解绑域名
miku repair          # 自动补依赖和核心，重启服务
miku port            # 修改管理端口
miku start
miku stop
miku restart
miku logs
miku backup
miku update /绝对路径/新版安装包.tar.gz
miku rollback        # 仅从旧 Miku 切换的安装：恢复配套旧版快照
miku uninstall       # 停止、取消自启，保留程序和数据
```

改密码、核心、域名等操作可能重启入口与 VPN；客户端会重新连接。
数据在 `/var/lib/miku`，程序在 `/usr/local/lib/miku`，服务名 `miku`。
备份包含访问口令、节点身份和证书私钥，文件权限为 600。

## 旧 Miku 安装

自动识别前一版已登记的 Miku 安装，先停旧服务并生成数据库、密钥、证书、程序、快捷菜单的配套快照，再用原普通账号导出。
可迁移自建入口、普通 OpenVPN 落地及其代理凭据。入口端口、UUID / 密码、REALITY 密钥尽量保持原值。
没有选过 OpenVPN 的空落地、带前置代理的落地及旧版高级记录不会变成空的新配置，保存在旧版快照中。
安装结束会打印新的网页登录口令。外部面板入口通过重新检测面板继续管理。
切换失败时恢复配套旧版；成功后可以用 `miku rollback` 恢复切换前状态。
恢复旧版后，新版数据仍保留，请勿直接混装两个服务。

此版使用 fanout 运行方式，旧版任务、远程 Agent、多账号等界面没有迁移到这个单页控制台。
VPS 上的实际 VPN Gate 连通、面板版本兼容和客户端连接由你最终验收；本次不替你操作 VPS。

## 当前功能（dev34）

- 登录页和工作台加入 Miku 插画、青绿色主题与移动布局，移除交流群、油管和博客入口；原 MIT 许可与项目署名保留。
- 默认包括全部 VPN Gate 节点。合并官方 API、Worker CSV 镜像、HTTPS CSV 快照、自定义 CSV，以及七天滚动池；移除无效的无 www API 地址，不再把网页镜像误当成 CSV API。滚动池固定提交并验证目录、配置文件和解码配置的 SHA256。镜像记录或 TCP 检查不能证明 VPN 在本机可用。
- 默认不设 20 条的软件总数上限，增加按钮可超过 20。可选 `-max` 仅供管理员自行限制；实际容量取决于 VPS 资源、端口与网络地址空间。旧网段保留，新槽位不会把 IPv4 八位字段扩大到 255 以上。
- 出口连接后异步查询 ASN、ASN 组织、ISP、IP 归属商、地理位置与 IP 属性。结果含来源、时间、分类依据与置信程度，成功缓存 24 小时；检测失败一分钟后自动重试。移动和机房明确标记优先；普通运营商网络结合类型字段与归属信息按住宅规则推断，不再要求完整双类型才能展示。代理 / VPN 标记不等于机房。IP-API 免费属性接口使用 HTTP，服务器只传查询的公网 IP；HTTPS 的 ipwho.is 提供 ASN/ISP 备用。可选 ipapi.is Key 通过服务端 HTTPS POST 使用，私有保存、不返回网页。遵守来源限流与429退避。
- 网页“域名 / 证书”支持多个域名，复用已有证书或安装 certbot 后申请新证书，选择是否设为 HTTPS 管理域名，也可解绑回 HTTP+IP。签发任务有进度，失败不会假装已绑定。
- TLS 新建表单自动列出管理、已有入口、Certbot、acme.sh 的有效证书；多域名可选择，自动填 SNI，节点链接使用选定域名。私钥不会返回网页；不匹配或过期证书不能被使用。无证书时可明确选择自签或手动证书。
- 注册的域名证书支持定时更新；OpenRC 使用 `miku certificate-refresh` 定期刷新。新域名须先解析到 VPS，ACME 独立签发需要80端口开放且空闲。已有入口使用的证书不会因移出域名列表而被删除。
- 出口卡片按“编号、IP位置、IP地址”展示，下面只列出 ASN 归属。凭据弹窗提供明确的“复制 SOCKS5”和“复制 HTTP”，主列表只保留编号、IP位置、地址、ASN和详情入口；使用母机发布地址，不把落地 IP 当成代理连接地址。
- 通过对应 OpenVPN 隧道、绑定 tun0 调用 Ping0 官方免费 `/geo`，读取实际出口位置、ASN 和归属商；失败时回退 HTTPS 出口 IP 探测。IP 属性仍由现有服务补齐并分别标注来源，IP详情可以直接打开 Ping0 网页检测。没有调用 Ping0 付费 API，也没有从免费定位结果猜测住宅、风控或原生属性。
- 新建、换线、连接失败、健康重连和重启恢复都严格保持最初选择的国家。原节点失败后自动尝试同国家其他节点，整轮失败会退避、刷新来源并继续尝试，不会换成邻国；近期失败节点冷却3分钟。Ping0返回可识别的国家时，实际出口国家不符的候选也会被拒绝。
- 来源列表仅显示本次可用来源，失败来源合并为简短提示；自定义 CSV 输入框缩短，API Key 输入保持页面样式。

本次完成离线构建与检查，VPS 的真实 VPN Gate 连通、DNS/ACME 签发、面板兼容和客户端连接仍由你验收。

## dev28 修复与订阅

- 入口跟随每个出口独立创建与修复，保存模板和稳定出口序号；连接晚于批量作业结束的出口也会自动补建入口。VPN已连通但入口失败会显示“修复入口”和原因，并自动重试入口；明确选择“仅 SOCKS5 / HTTP”时使用代理凭据。
- 同批节点在启动前全部占位，并发重试对主机名和IP原子占用；连接成功还会检查实际出口IP重复。失败候选的旧OpenVPN进程会被终止，避免遗留连接占用。
- 旧版凭据、传输与安全层完全相同的自动入口副本会停用多余副本，原端口和凭据继续保留；停用副本不再显示为可用端口；手动不同凭据入口不合并。原入口在换线后继续跟随出口，断开出口不会变成直连模板。
- “新建节点 → 粘贴本 VPS 已生成的节点链接 → 确认识别”核对本机发布地址、端口、凭据与完整传输参数。匹配后关联已有入口，可点“用作模板”批量创建出口，不新建重复监听；SOCKS5 / HTTP 会核对本机出口凭据。外部链接会被拒绝；旧外部导入记录保留在磁盘，但不再显示或进入订阅。
- “新建出口 → 添加VPN Gate来源链接”和“设置 → 添加来源”可粘贴公开OpenVPN CSV地址，确认时先检查有效配置再保存与加入候选池。来源列表的上下箭头会立即保存优先顺序并改变节点选择；默认仍为近期检测、开源快照、社区镜像、官方兜底。来源优先级不是客户端IP检测服务顺序。
- 订阅弹窗选择通用Base64、V2Ray/v2rayN Base64、Clash/Mihomo YAML或sing-box JSON后复制地址；原订阅口令继续沿用。分享链接按连接配置去重，不导出已停用客户端或失联的绑定。VMess使用标准Base64 JSON分享方式。
- Clash使用支持VLESS/REALITY的Mihomo内核；V2Ray/v2rayN订阅中REALITY由Xray内核运行。sing-box JSON含本地127.0.0.1:7890混合代理入口和节点选择器。XHTTP目前请使用通用/V2Ray格式；不支持的格式返回明确错误，保留客户端上一份订阅。sing-box导出的整张证书SHA256固定指纹字段需要1.15+客户端；不会通过关闭证书校验来假装兼容。
- 登录文案改为“世界就在那一端，和我一起，让连接的旋律响起来吧。”和“一起连接世界”。

已做Go离线回归、页面交互检查和amd64/arm64编译；真实VPS上的VPN Gate连通、域名证书与客户端导入由你最后验收。

## dev30 展示模式、IP 类型与总延迟

- 出口列表右侧增加“展示模式 / 管理模式”切换，并记住当前浏览器的选择。沿用 Miku 青绿色、深色面板和插画。
- 移除展示模式的地区统计卡片、类型筛选、搜索框和说明栏，工具栏下面直接显示出口卡片。保留连接状态、节点端口、位置、ASN，以及复制节点、SOCKS5、HTTP和切换IP。
- 类型检测参考 AimiliVPN 的网络归属判断：优先使用 IP-API 的 `mobile` / `hosting` / 运营商信息，保留 ipapi.is 双类型规则，疑似机房或缺少字段时尝试第二来源；缺少 ASN 时由 ipwho.is 补齐。Key 可选，匿名接口缺少的字段不会覆盖已有有效标记。普通网络的住宅标签属于规则推断，详情展示来源、判断依据与置信程度；全部来源不可用时显示“检测失败”并自动重试，未完成时显示“检测中…”。升级自动重新判断并刷新旧类型缓存，修改 Key 后再次刷新。
- 总延迟为 **当前浏览器到 VPS 的 HTTP 往返时间 + VPS 到当前 VPN Gate 服务端的实测往返时间**。本地段先预热同源连接，再取三次测量的中位数；服务端优先 ICMP 平均值，失败时测配置中的 TCP 端口，并显示测量方式。dev32 增加隧道参考值，具体测量路径和超时规则见下面的说明；不使用 VPN Gate CSV 的 `Ping` 列填补。浏览器不支持直接发 ICMP；管理地址经过反向代理或 CDN 时，本地段包含该路径开销。
- 停用入口不再挂到出口；共享监听器按客户端的实际出口归属显示和复制。自建模式重复使用同一模板不会新增同样的监听端口。不同配置的有效入口保留，在卡片中用下拉框选择，每次复制对应当前选项。
- 分享链接连接本 VPS 发布地址或已登记的入口证书域名；SOCKS5与HTTP连接本 VPS 的认证混合代理端口。出口IP只显示为流量落地地址。
- 粘贴链接识别现有本机入口，不作为任意远程节点导入；凭据重置、入口停用或删除后，旧记录不会绕过订阅过滤重新出现。

类型判断思路参考 [AimiliVPN vpn_utils.py](https://github.com/OpenMili/aimili-vpngate/blob/main/vpn_utils.py)，字段依照 [IP-API 文档](https://ip-api.com/docs/api:json)和 [ipapi.is 文档](https://ipapi.is/developers.html)实现。住宅分类是本项目的展示规则，不代表来源对家庭宽带属性的认证。

升级时用新版安装包运行 `sudo bash miku-fanout/install.sh`，或执行 `sudo miku update /绝对路径/miku-fanout-vps-dev34.tar.gz`。安装器沿用现有配置。已有重复自动入口在出口恢复、重连或“修复入口”时对账停用，保留选中入口的端口及凭据。

VPS 新安装及升级时自动补齐 `ping` 依赖（Debian / Ubuntu 为 `iputils-ping`，其他支持系统为 `iputils`）。服务端不响应 ICMP 时自动尝试备用测量；全部方式暂不可用会显示“暂未测得”，稍后重试。

## dev32 延迟与断线重连

- VPS 先发两次 ICMP ping，失败后测当前 OpenVPN 配置中的实际 TCP 端口；同地址的 ICMP 失败冷却 5 分钟，期间直接尝试 TCP。UDP 端口不会被当成 TCP 服务，不猜测 443 端口。8 个检测任务并发执行，缓存区分地址、协议与端口，切线后不沿用旧端点的结果。
- 只有 UDP、屏蔽 ICMP 或 TCP 测量失败时，复用成功隧道 HTTPS 检测中的 TCP 建连时间，扣除 DNS 时间，标为“参考总延迟 / 隧道 TCP”。它包含 VPS 经 VPN Gate 到检测站的路径开销，再加本地到 VPS 的浏览器 RTT，不能等同于严格的 VPS→Gate ping。悬浮说明和分项会写明此区别。隧道样本只使用 45 秒内结果；直接测量超过 90 秒不再展示，浏览器测量超过 60 秒也不会继续相加。
- 健康检测改为 8 个有上限的并发任务，每个出口不重复排队；主站不可用时尝试另一检测站。两者都绑定该出口的 `tun0`，绕过环境代理，并核对实际出口 IP；连续两次失败才自动重连。测不到 ping 不会单独触发断线判断。
- 每轮预检最多 6 个同国家候选，每出口同时检测最多 3 个，全局最多 12 个。优先可达且同 ASN、同地区的候选，其次同 ASN，再选同地区或同国家其他可用节点；TCP 明确失败者排到最后。UDP 的 ICMP 超时只视为未确认，仍可实际建隧道验证。原候选失败后继续同国家重试，全部失败会退避并刷新来源。
- 原出口首次确认的 ASN、地区偏好随状态保存，临时换到其他同国家运营商也不会覆盖原偏好。真实出口国家必须与最初选择一致；优先用隧道内 Ping0 的实际定位，备用查询实际出口 IP 的有效归属缓存或批量接口。超过 24 小时的归属不作为确认依据，无法确认时等待重试，不假装匹配，也不把查询站故障记为 VPN 节点死亡。
- 批量归属请求最多包含 6 个去重公网 IP，每 5 秒最多一次，遵守 IP-API 的 `X-Rl` / `X-Ttl` 和 429 退避。预检结果不能替代 OpenVPN 握手、出口身份和重复出口校验。停止、切线或槽位被复用后，旧健康检测结果会被丢弃；端口、入口身份与代理凭据继续沿用。

## dev33 稳定性提示与测量频率

- 每个出口分别统计最近 10 分钟内由健康检查触发的自动断线重连，第 4 次起显示暖色“连接稳定性提示”和次数。文案为：“当前 VPS 与该地区的连接近期可能存在波动。为获得更平稳的使用体验，建议尝试其他地区。”这是基于近期重连情况的建议，不将波动直接归因于 VPS 或地区。
- 提示放在对应出口内，管理模式、展示模式及正在重连时均可见。窗口滚动到不超过 3 次后自动消失；第 3 次不显示。手动切换 IP、开机恢复、一次重连内部尝试多个候选不增加次数；被丢弃的旧健康结果不计数。记录随状态保存，重启后仅保留窗口内有效记录，新出口不继承旧槽位的次数。
- 本地到 VPS 的浏览器测量和 VPS 到 Gate 的常规测量均限制为每 30 秒一轮，失败也遵守该间隔。浏览器同标签页刷新、快速切换前后台会复用间隔和有效结果；浏览器存储不可用时仍在当前页面内限频。
- 健康检查继续独立判断是否断线，已产生的隧道检测时间最多每 30 秒更新一次延迟参考值，不为参考值另外发送 HTTPS 请求。页面三秒轮询仅更新显示和状态，不会绕过 30 秒限频。首次连接和换到新端点时可以建立首个样本，重连候选的可用性预检继续按需进行。
