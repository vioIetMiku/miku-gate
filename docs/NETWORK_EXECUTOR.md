# 网络执行器：下一阶段实施契约

> 更新于 2026-10-09。dev.2 已实现独立的 quarantine-only CLI：仅创建不联网的 namespace 和其内部全阻断 nftables 规则。没有 TUN、OpenVPN、业务 DNS、代理监听或特权 IPC；完整数据面仍为下述实施契约。

## 当前已实现的隔离底座

- 稳定实例 / 出口 ID 派生资源名；认证后的只读计划 API 与 CLI 共用计划。
- root CLI 与普通用户 Web 服务分离；CLI 不接受任意命令、配置文件路径或 shell。
- 独立 namespace 内全丢弃 IPv4/IPv6；不创建外部链路，不改宿主路由或规则。
- 原子归属记录、flock、NSFS 文件描述符与 inode 校验、结构化 nft JSON 核验。
- 幂等准备、显式清理、未知归属保留、独立超时回滚和 32 个沙箱预算。
- 单元故障注入与可显式启用的双 namespace Linux 实验；实际执行结果见 PROGRESS.md。

操作说明见 [LINUX_SANDBOX.md](LINUX_SANDBOX.md)。这些内容不代表后续建连闭环已完成。

## 不得绕过的能力闸门

当前 `/api/exits/{id}/start` 明确返回不可用。解除闸门必须同时具备可工作的执行器、受控 Linux 端到端测试、失败注入测试，以及 API 中对真实实际状态的报告。

不允许为了演示而把状态直接改成 active，也不允许用 `net.Dial` 的宿主默认路由暂时替代 VPN 出站。

## 最小闭环

1. 用稳定实例 ID / 出口 ID 派生本实例专属网络对象名，不使用通用 `tun0`。
2. 控制面作为普通用户运行；独立特权执行器仅接受有限的结构化操作，通过受限 Unix socket 校验调用身份。
3. 创建 namespace 后先安装默认拒绝规则，再开放唯一允许的 VPN 端点底层路径。
4. 保存配置来源和经过校验的配置，固定运行参数、文件归属和目录，不接受任意命令、插件或脚本钩子。
5. 启动官方 OpenVPN，隔离业务路由；宿主上的管理、数据库及普通应用不进入该 namespace。
6. 出站 socket 和业务 DNS 都由指定 namespace 里的拨号器创建，禁止宿主解析回退。
7. 在已建立隧道内验证出口、DNS 和目标规则，再打开对应逻辑入口的数据转发。
8. 故障时保留内核阻断，更新实际状态，受限退避并恢复；不先拆保护再重连。

Go 的线程、子进程和 namespace 归属必须显式控制，特别验证新线程、fork/exec、Xray 子进程及监听 socket 不会继承错误 namespace。

## 测试拓扑

优先使用本地受控的 OpenVPN 服务器和目标服务，限制在隔离实验网络，不以大量连接公共志愿者节点作为自动测试。

必须覆盖：

- 多出口并行，指定出口 IP 与实际流量一致。
- VPN 进程退出、TUN 消失、网关不可达和 DNS 超时。
- 已有 TCP 连接、新连接、半开连接和客户端主动取消。
- IPv6、IPv4 映射地址、私网、回环、链路本地、云元数据及 DNS 重绑定。
- 创建各阶段异常、协调器崩溃、重启接管和资源归属冲突。
- 宿主有其他 VPN、Docker 或防火墙规则时不破坏它们。
- 卸载只清理归属于 Miku Gate 的对象。

抓包和受控目标的观测是判断路由、防泄漏是否通过的依据；进程存在、界面显示连接和一次 HTTP 请求成功都不够。
