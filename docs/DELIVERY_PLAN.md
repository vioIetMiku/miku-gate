## 正确的数据路径

用户客户端 → 已有或Miku管理的Xray/sing-box加密入口 → Miku逻辑出口的本机认证代理 → OpenVPN隧道或用户指定HTTP/SOCKS上游 → 目标服务。

VPN Gate主要发布OpenVPN等VPN协议，不把列表中的IP误当成HTTP/SOCKS代理。HTTP/SOCKS上游是独立可选的出口来源。管理域名与REALITY伪装目标不是同一个概念；REALITY候选不要求归用户所有，管理/TLS域名则必须满足真实控制权与证书要求。

“纯净度”没有通用可靠的单一分数：展示测得的出口IP、ASN/托管类型、可选信誉来源与时间；不存在证据时明确未知。CDN域名的解析位置不等于网站经营者所在地。

## 实施顺序与发布门槛

1. **真实代理运行时**：完成HTTP/SOCKS/HTTPS上游、经上游的业务DNS、加密保存上游凭据、启动/停止/取消/状态/本机认证监听。为OpenVPN保留同一驱动接口，不用代理模式代替R08。
2. **生产OpenVPN执行器**：最小权限worker、受限生命周期、连接交接、受控与真实节点验收，接通同一逻辑出口入口。
3. **安装与主机向导**：只读清单、依赖确认、域名或IP管理地址、现有核心检测/复用/保留/替换确认、TLS资产管理。
4. **加密入口与出口选择**：Xray/sing-box模板、REALITY候选探测、自定义目标、节点/域名/ASN与信誉信息、分享连接和端到端测试。
5. **发行及最终验收**：多平台归档、安装/升级/回滚、低资源VPS、完整浏览器旅程与文档；逐项复核R01–R13后才宣布整个项目完成。

每个里程碑都可独立发布预览版，但不能把预览版定义为整个目标完成。不创建开放代理，不无声接管3x-ui管理的配置，不把实验启动助手作为生产服务，不通过关闭noexec、TLS校验或宿主防火墙完成验收。
