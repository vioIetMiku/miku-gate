# 已安装Miku的配套私有备份（dev.11开发）

## 为什么不是只复制数据库

逻辑出口/入口材料由数据库同名`.key`加密：备份必须包括正确实例数据库、WAL/SHM（若仍存在）、vault key、TLS管理副本和已登记安装单元/程序摘要。不允许用缺key的归档冒充可恢复，不把旧二进制单独换回当数据库schema回滚。

`sudo python3 -B /usr/local/lib/miku-gate/miku-maintain.py status`只读核对安装归属和服务状态。`backup`需明确`--confirm-stop --confirm-backup --output=全新绝对文件`，root私有0700父目录、新归档0600。只操作安装登记的固定资源，不按浏览器/归档里的任意路径执行命令，也不递归删除旧目录。

## 当前实现

1. 读取root0600 install-state，核对专用账号UID/GID、稳定实例、二进制SHA256和当前独立数据目录权限；程序漂移/未知旧安装拒绝，不自动接管。
2. 记录已活动的确切Miku管理/VPN单元，明确停机并确认没有剩余MainPID。持有数据目录`.serve.lock`租约，手工未知控制进程仍运行时拒绝。
3. 同专用普通UID只读检查SQLite身份/schema6/integrity与加密行数量，避免root检查创建root所有WAL/SHM污染数据目录。
4. 列举有限已知文件名，不含未知数据目录；每个普通文件单链接、权限/所有者/路径核对，新安装一并保存已登记root所有的安装/维护协调器；最大文件48MiB、总96MiB，超预算停止而不是漏备份。核心ELF不纳入此数据归档，保留固定核心来源/摘要，不宣称独立可离线恢复全部运行程序。
5. 用检查后的父目录FD独占创建归档，manifest记录成员名/大小/SHA256/所有者/权限，归档全部普通文件，完成后不解压逐项读回比对。成员路径重复、父路径穿越、链接、类型/大小异常拒绝。
6. 默认恢复之前活动的确切Miku服务，并验证真实HTTPS叶证书/Host健康；有VPN还由授权普通UID核对执行器instance与工作UID。失败不吞掉restart错误。`--leave-stopped`明确保留停机，不假称已恢复服务。

备份归档含原始敏感钥匙和证书，所以不是公开发行/Issue附件。`.key`文件和TLS私钥不能从归档导入前端展示。每次创建新文件；未确认停机/备份或已存在输出都会停止，不覆盖/删旧归档。

## 验证及边界

离线测试覆盖未知/重复成员拒绝、目录独占/完整内容比对；Windows不冒充Linux文件权限通过。实际安装CI新增受管HTTPS账号登录、保存一条真实加密上游、配套DB/key备份、归档内容/私有权限核验、服务重启后加密材料可读取、身份不变。结果需要精确CI回读，新增用例不等于已执行成功。

**restore/upgrade/uninstall尚未实现**，metadata保持restore_verified=false。备份后服务重启不证明从归档还原成功。升级必须有自己的变更计划、配套数据备份、数据库迁移、健康验收和可验证回滚；此脚本是必要底座，不替代这些最终交付要求。用户现有VPS未执行此永久安装备份，当前只在可丢弃runner验证。
