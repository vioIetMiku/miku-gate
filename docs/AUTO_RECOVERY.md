# 自动恢复与同国家候选换线（dev.14主线）

> 默认关闭。只在管理员明确保存恢复设置后，才允许故障及控制服务重启后联网；用户点击停止出口会持久关闭自动恢复。旧dev.13发行不包含本功能。

## 在界面设置

出口详情 → 真实运行状态 → 自动恢复/同国家换线。可选择：启用恢复、恢复Miku受管加密入口、候选允许明确VPN Gate旧数据算法兼容、最多3个同国家备用节点。留空候选只重连原VPN或用户自备HTTP/HTTPS/SOCKS上游，不把代理上游暗中切成VPN。不旋转监听端口、用户名、代理密码、VLESS UUID/Trojan密码/REALITY密钥。

保存需要管理员会话、CSRF/同源与明确联网确认。仅元数据策略持久，节点身份检查不是浏览器上传的“可信”标志；候选必须当前官方缓存、同逻辑出口国家，24小时新鲜政策，每次尝试重新检查。不在无证据时绕过严格住宅政策，不跨国家自动换线，也不承诺住宅/纯净。

## 故障处理和预算

1. 出口健康时不联网查询其他候选，也不换线。已有健康检查失败或VPN执行器会话死亡时取消入口会话/监听/正在传输的连接，不继续监听伪装健康。
2. 默认每5秒检查一次本地状态；一次只恢复一个出口/尝试一个候选，先确认受管核心与原出口停止，未确认停止不开始替换。候选失败不马上扫下一台。
3. 首次退避30秒，指数增长至15分钟；每次恢复最大45秒，候选TLS身份探测最多5秒，遵守当前官方域名/系统CA/SAN和精确指纹，保存加密VPN快照后独立执行器验证真实业务DNS/TLS/出口IP，才开放认证监听。
4. 原上游模式只重连原配置；无候选、缓存过期或全部失败就持续停止/退避。没有宿主直连或宿主DNS后备。不自动刷新整个节点库、不反复压测志愿节点。
5. 开启受管入口恢复时只对Miku自己的子核心操作，REALITY目标重新探测并更新目标素材，已有客户端身份保留；证书失效/核心不匹配时入口保持停止并显示原因。面板入口自身不由Miku启动/停止，故障时只连接到不可用本机SOCKS，选定路由仍不会变direct。
6. 人工启动、停止、更新出口配置与恢复每出口串行互锁。用户停止先持久pause再取消正在进行的恢复，等待取消后停入口/出口，防止“停了又自动开”。控制程序关闭会取消恢复任务，并在数据库关闭前等待任务结束。

## 状态与不确定性

GET `/api/exits/{id}/recovery`显示策略、healthy/recovering/backoff/paused、连续失败/下一次时间/当前候选/入口未恢复原因。PUT保存确认设置。metadata中只有非秘密策略，删除逻辑出口同步删除策略；端口和身份仍由原加密配置/口令摘要保管。

## 本批检查范围

新增仅内存状态的候选顺序/失败退避/健康不查询/用户停止取消用例；真实store的国家/来源/新鲜度/代理不混用/重启策略持久检查；实际gateway恢复到相同监听和原用户名密码的回环SOCKS认证，再pause后不重新开。业务session为明确受控夹具，不能作为真实公共VPN自动换线、内核长期保护或用户VPS长稳证据。

当前仍待真实公共候选故障→另一节点→客户端出口IP切换专项和长期installed systemd旅程。只执行新增路径检查，不重放旧公开VPN实验；目标完整性保留，不以“有自动恢复代码”宣称全部项目完成。
