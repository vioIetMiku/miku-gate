# VPN Gate 配置兼容政策（dev.7开发中）

> 静态配置兼容不等于成功连接。生产OpenVPN生命周期/worker及可信服务器名称来源仍在接线；此页不解除启动闸门，不把旧算法支持当作住宅、信誉或服务器身份背书。

## 来自真实官方列表的观察

2026-10-10，从授权VPS读取官方HTTPS API一次完整列表：100条配置，82个TCP、18个UDP；全部指定`AES-128-CBC`与`auth SHA1`。原严格AEAD策略会拒绝这批配置，不应只把它们显示成可运行节点。

三个缓存样本的服务器CA为ISRG Root X1（SHA256签名、RSA4096、CA用途、2035年到期）；客户端是公开共享的`VPNGateClientCert`（RSA2048、自签SHA1、2037年到期），它并不是由ISRG签发的客户端证书。服务器CA与客户端身份不能混为一条证书链。

- 官方列表响应SHA-256：`bc53de16accd3df3f69c87ca52d4d6e0a1c097a44bf86a9c8ce7cbd4918d379f`。
- ISRG根DER SHA-256：`96bcec06264976f37460779acf28c5a7cfe8a3c0aae11a8ffcee05c0bddf08c6`。
- 公开共享客户端DER SHA-256：`5f63774f1fc257f26108a02ca6b18fa9131bb48a36dfd75edd13fdbe2e5ca47c`。

原始配置只保留在root私有实验目录，私钥不写入Git或API响应。本机首次官方API请求未连通；VPS首次统计因编码名拼写错误未完成，修正后的统计才构成上述证据。未因此关闭HTTPS验证，也未在调查中连接公共VPN节点。

## 默认严格，兼容需要明确选择

`Normalize`仍保持原AEAD、强证书、固定端点策略。新`NormalizeWithOptions`只有在`AllowVPNGateLegacy=true`且提供合法的`ExpectedPeerName`时，才允许受限兼容：

| 内容 | 兼容模式 | 仍然拒绝 |
| --- | --- | --- |
| 数据通道 | 在AEAD候选后增加AES-128-CBC，并设置对应fallback；HMAC-SHA1 | BF-CBC、3DES、任意CBC、未知认证算法 |
| TLS服务器 | 保持TLS≥1.2、服务器角色/CA校验和明确预期名称 | 关闭证书校验、SECLEVEL=0、tls-cert-profile insecure、TLS1.0 |
| 客户端身份 | 仅精确指纹匹配的公开共享证书例外，且公私钥必须匹配、有效期与位数仍核验 | 相同CN但不同证书、任意SHA1证书、错误私钥、过期共享身份 |
| 源配置 | 重建固定参数、封印配置、隔离路由/DNS | 脚本、插件、include、外部认证文件、任意环境变量、压缩 |

HMAC-SHA1是数据通道消息认证算法，不等同于允许SHA1服务器证书签名。共享客户端证书的例外也不把该证书加入任何服务器信任根。客户端凭据本来公开，不能作为隐私或运营者可信证明。

若源配置已经使用现代算法，单纯打开兼容选项不会自动降级为CBC。源文件存在与预期服务器名称冲突的检查时，拒绝配置而不是覆盖它。不能根据一个刚观察到的证书名称自动“信任并重试”；服务器身份绑定仍需独立可靠来源。

## 控制台静态检查

`GET /api/nodes/{id}/profile`只处理已认证用户的官方来源缓存，不访问网络、不执行OpenVPN，不返回CA、证书、私钥或可执行配置。界面可显示：

- `strict`：符合严格格式/材料政策；不是连通证据。
- `legacy-candidate`：符合受限兼容候选格式，仍需明确同意和可信名称绑定。
- `unsupported`：格式、材料或策略不支持；不尝试运行。

所有静态响应的`network_tested`与`server_identity_verified`都为false。没有预期名称的候选只在内存里用不可部署的分析标签检查结构，随即丢弃；该标签不返回、不得存入运行时。查看弹窗不等于同意连接。

## 验证门槛

已加入默认不降级、显式同意/名称必需、恶意指令不放宽、非精确共享证书拒绝、API不泄露/不写状态、浏览器弹窗测试，以及有界fuzz。真实OpenVPN实验扩展为两条旅程：AEAD与显式CBC/HMAC，各自保留错误服务器名称负向对照、DNS/TCP、断线和底层绕行阻断。CBC旅程还必须在OpenVPN日志看到实际协商的AES-128-CBC，而非仅检查配置文本。

实际执行已在478f914完成：两个原生OpenVPN旅程与三个官方样本静态分类均通过，见[独立验收](validation/2026-10-10-vpngate-compatibility.md)。实验强mTLS身份与官方旧共享客户端身份不同，后者仍仅通过静态材料校验，不能外推为公共握手通过。既有dev.6 Release不可替换，新的政策只在main/dev.7开发中。
