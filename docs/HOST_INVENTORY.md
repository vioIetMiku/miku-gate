# 主机与已有服务：只读检测（dev.9 开发）

## 使用

Linux 上执行 `miku-gate inventory`，或登录控制台 → 系统与诊断 → 主机与已有服务 → 检测已有服务。命令输出 JSON，不初始化数据库、不安装依赖；不接受用户提供的扫描目录或 shell 命令。API 为 `GET /api/host/inventory`，需要登录，同源限制与其他管理接口相同，15 秒短缓存、最多一次并行检测、6 秒总预算。

## 当前能确认什么

- Linux 发行版/架构、检测权限、TUN 设备类型、systemd 运行目录。
- OpenVPN、ip、nft、nsenter、setpriv、systemctl 是否可在 PATH 找到及用途/软件包提示。
- 3x-ui/x-ui 常见安装路径、内嵌 Xray、独立 Xray、sing-box、Nginx、Caddy 文件存在性；只取文件类型，不打开内容。
- 固定 systemd 单元的 LoadState、ActiveState 和 MainPID；调用经过 root 所有权/权限检查的固定 systemctl，不执行发现的核心/面板程序，不读取进程命令行/环境变量。

`detected` 表示存在安装痕迹，不是“节点已可用”。`not_detected` 仅指常见路径/单元未发现；权限拒绝、符号链接、类型异常或查询失败为 `unknown` 或明细异常。Windows 明确显示不支持本机 Linux 检测，不拿 Windows 结果冒充 VPS。

## 尚未完成的安装向导部分

这不是完整清单和复用器：自定义目录、容器、模板单元、核心版本与端口归属尚未覆盖。3x-ui 与 x-ui 共用常见路径，当前不猜分支和版本。`reuse_ready` 保持 false；下一阶段需有约束地解析配置、确认端口与入口能力、用户选择、备份、应用和回滚。

无任何自动安装/替换/重启操作，也不直接读取面板数据库、私钥或客户端凭据。工具存在不等于版本满足要求，`package_hint` 不是未经确认可以执行的安装命令。最终脚本会先展示依赖与变更计划并征求确认，不能用本阶段只读检测代替该交付目标。

## 验证

单元测试覆盖文件/权限/符号链接的不确定性、已安装但未授权复用、信息最小化、元数据枚举、取消及不支持平台；API 测试覆盖认证/Origin、缓存和并行限制。真实 HTTP smoke 与 Chrome 旅程覆盖点击检测、响应、桌面/390px 布局。Linux 主机实测记录应另按精确提交保存。
