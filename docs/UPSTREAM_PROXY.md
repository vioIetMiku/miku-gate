# 代理上游与业务DNS

> dev.6开发预览，已接入Web与CLI的真实代理上游运行时。完整目标仍包含OpenVPN、Xray/sing-box入口、域名/TLS/REALITY向导和交互安装，见 [交付矩阵](DELIVERY_PLAN.md)。这不是用HTTP/SOCKS替代VPN Gate的OpenVPN出口。

## 数据路径

认证HTTP/SOCKS入口 → 选定的SOCKS5、HTTP CONNECT或HTTPS CONNECT上游 → 已验证的公网IPv4目标。

HTTP/SOCKS上游是用户另外提供的代理服务；VPN Gate的OpenVPN节点不能直接填写为HTTP/SOCKS代理。每种上游都需要正确协议，连接失败只报错，不直接连接业务目标。

业务域名通过同一上游建立到Cloudflare或Google固定数字端点的TLS连接，提交标准DNS-over-HTTPS报文。完整校验TLS服务器身份、DNS事务/问题/A/CNAME及大小，所有候选IP均通过公网策略后，只把数字IP交给上游。混入私网、环回、元数据或IPv6会拒绝整个结果。DNS失败没有hosts/NSS/search或宿主DNS后备，也不会换成宿主HTTP代理环境变量。

**区别：** 上游服务器本身若用域名配置，会由本机控制面解析一次、验证全部地址并固定数字端点；只有业务DNS被要求走上游。不要把这个设计表述为“宿主完全不发出任何DNS”。

## 认证与TLS

- SOCKS5提供凭据时只协商用户名/密码方法，拒绝匿名降级。
- HTTP CONNECT凭据只发给指定上游，不透传客户端的代理密码。
- HTTPS CONNECT必须验证证书，TLS1.2最低版本；可指定与证书匹配的TLS服务器名，不提供跳过验证选项。
- 远程明文HTTP/SOCKS必须显式确认风险；回环上游仅允许明确选择的`127.0.0.1`非特权端口。
- 不允许私网/元数据上游；域名解析到环回也不能借用回环开关绕过地址策略。
- 本轮业务支持TCP4，IPv6/UDP不是隐式直连后备。

上游运营者仍可能观察或篡改未端到端加密的业务；代理本身并不证明住宅属性、匿名性或节点信誉。DNS探测成功也不代表已核验公网出口IP，二者使用不同状态字段。

## 加密保存与升级

SQLite schema v3新增加密上游记录。AES-256-GCM每次写入使用随机nonce，附加认证数据绑定稳定实例ID与出口ID。上游用户名/密码不以明文写入数据库；API视图和格式化输出不包含密码。

密钥位于数据库同名`.key`文件，首次保存上游时才创建；Linux要求当前服务用户所有、0600、普通文件、单硬链接，不允许符号链接/FIFO等对象。非Linux开发环境还必须依靠OS ACL保护数据目录。这个机制只防止单独泄露数据库暴露上游密码，不能对抗同时读到密钥或进程内存的攻击者。

已有加密记录而密钥丢失/损坏时拒绝打开，不覆盖、不生成新密钥伪装恢复。备份/恢复需包含数据库及其配套密钥；升级前停止服务并备份完整数据目录。旧dev.5及更早程序不能读取schema v3。

复用已有密码只允许相同协议、地址、端口、TLS身份与用户名；修改目标必须明确提供新凭据，避免把旧代理密码发送给另一个服务器。

## 运行与状态

默认`serve`开启代理上游运行时，但不会从保存配置自动打开监听。需用户在控制台或API明确启动；`--control-plane-only`保留无运行时的管理模式。每个数据目录由OS排他锁保护，第二个控制服务不能绕过内存互锁修改同一批配置。`instance`改为只读查询，不因查看ID触发迁移或读取凭据密钥。

- 先验证凭据材料、上游协议/TLS与经上游DNS，再绑定固定的127.0.0.1入口；端口被占用时只报错，不终止其他服务。
- 默认最多3个同时存在的启动/运行/关闭会话，每个入口最多64连接。首次成功认证核验Argon2，随后用进程内随机密钥的HMAC缓存，避免每条连接重复分配64MiB；未通过的密码不会进入缓存。
- 配置、凭据、删除与沙箱变更仅允许停止时进行，同一出口的操作有互锁；不同出口不会因长操作持有全局互斥锁。
- 每30秒经同一上游复测DNS/TLS；失败显示degraded而不回落直连。也可以手动“检测连通性”。这是探测耗时，不是ICMP ping或带宽测试。
- 停止会取消启动/探测，关闭监听和已接受的连接，等待处理协程退出，并关闭上游会话。配置状态不作为存活证据。
- `running`和`degraded`表示实际入口仍在监听，`healthy`区分最近探测结果；`proxy_only`不代表内核隔离，`kernel_verified`保持false。

接口、错误码和更新规则见 [API.md](API.md)。本阶段没有自动恢复、热切换或公网出口IP查询，完整后续范围仍由交付矩阵追踪。

## 已验证与后续接线

本机真实私有监听测试已覆盖三类上游、TLS与DoH、认证HTTP前端到上游到目标、缓冲payload保留、认证降级拒绝、TLS名称拒绝、混合私网DNS、DNS超时/重定向拒绝、上游失效无直连后备，以及关闭既有连接。DNS解析器仍由原有隧道测试和fuzz种子覆盖。

API/运行时已通过实际HTTP请求、加密存储、认证代理监听、配置互锁与停止回归；浏览器使用真实服务，覆盖上游表单、密码不回显、拒绝上游的失败反馈与移动布局。协议/TLS/DoH层使用真实私有测试服务；API测试中的出站会话工厂是受控替身，不能据此宣称公共代理或目标VPS已验证。目标环境另行记录。下一步是生产OpenVPN worker与生命周期，再完成加密入口/域名/安装向导。
