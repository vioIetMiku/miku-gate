# Miku Gate 最终功能对齐稿

> 用于用户确认最终产品形态，不是“当前已经完成”的功能清单。现有代码、Release和验收状态仍以PROGRESS及独立验证记录为准。本文补充解释完整交付矩阵R01–R13，不删除原目标，也不把预览版定义为项目完成。

## 一句话定位

稳定的客户端入口 + 可选择、检测、切换和恢复的出口 + 不破坏已有面板的安装运维控制台。

核心路径：客户端 → VPS上的已有或Miku管理的加密入口 → Miku逻辑出口 → OpenVPN隧道或HTTP/SOCKS代理上游 → 目标网站。切换出口不要求重新更换客户端入口地址；网站通常看到的是实际出口IP，而不是入口IP，但必须通过真实探测确认。

## 1. 交互式VPS安装与首次配置

1. 只读检查发行版/架构、内存/磁盘、权限、TUN、systemd、所需工具、端口、防火墙，以及3x-ui/x-ui、Xray、sing-box、Nginx/Caddy和现有证书。
2. 列出确实缺少的依赖及用途，询问是否安装；拒绝后停止相关功能安装或清楚提示缺失项，不偷偷继续。不同核心按选择安装，不把所有组件强装一遍。
3. 询问管理界面使用域名还是VPS IP；有域名则校验解析与证书条件，无域名则输出实际VPS IP及管理端口。不把永久SSH转发或强制买域名作为最终使用条件。
4. 检测已有节点工具，展示版本/配置归属/端口及可复用范围。让用户选择复用已有入口、并行新建Miku受管入口，或在明确备份确认后迁移到另一个核心。
5. 创建项目专用账号、权限隔离和systemd服务，配置必要的入口端口；更改防火墙/反代前明确展示并询问。绝不抢占既有80/443、覆盖整份面板数据库或全局重启Xray。
6. 一次性生成管理账号和独立入口凭据，给出可访问管理地址、客户端导入方式、后续修改入口。用户不需要手填namespace、Linux UID或worker参数。

管理端默认采用受保护传输。有域名时优先受信任HTTPS；IP模式也要有明确的证书信任/验证方案，不能把自签证书标为浏览器默认信任，也不能默认公网裸HTTP处理密码。SSH转发可保留为额外安全方式，不是唯一方案。

## 2. 入口节点：复用或新建

- Xray和sing-box都是受支持的可选核心；设置中能查看、安装、切换Miku管理的核心与配置，操作前预览影响、备份、校验，新实例健康后再接替。
- 重点模板：VLESS + TCP/RAW + TLS + xtls-rprx-vision；VLESS + TCP/RAW + REALITY + Vision。兼容用途可提供VLESS + WebSocket + TLS等独立模板，但不错误组合不兼容的Vision/传输参数。
- 可设置监听端口、客户端/设备凭据、接入范围和限额，生成分享链接/二维码与受保护订阅；撤销一个设备不必修改全部设备。
- 既有3x-ui继续拥有其管理的配置；Miku优先修改明确授权、可追踪的独立入站/路由项。不能安全协同的版本明确提示或改用并行入口，不让两个控制器反复覆盖配置。
- 新旧入口与逻辑出口是分开的对象：一个入口可绑定指定出口；可建立多个独立国家/用途出口，某条故障不修改其他出口或宿主网络。

## 3. TLS证书与REALITY候选

TLS模式：检查现有证书的SAN/域名、有效期、公私钥匹配、用途和文件权限，支持用户确认后复用适配的Nginx/Caddy/ACME/面板证书。不需要用户把私钥复制到浏览器。无合适证书时提供ACME签发指引/流程，先检查端口和DNS条件；DNS API授权仍需用户确认。续期、到期提醒、热更新与失败回滚纳入运维。

REALITY模式：生成独立私钥/公钥、shortId等参数，列出约10个候选目标并实际检测TLS能力、可达性和必要的核心兼容条件；也允许自填域名。候选带检测时间与原因，不凭域名大就保证可用。当可验证目标不足时如实说明，不用未检测条目凑满。管理域名/TLS域名和REALITY目标分别显示，避免混淆归属；另对未认证fallback转发设置必要限额，避免把VPS变成可被滥用的通用中继。

## 4. 出口节点：OpenVPN与代理来源

- VPN Gate：官方来源节点同步、筛选、缓存、收藏/标签；OpenVPN TCP/UDP作为VPN传输，按真实配置和明确兼容政策建连，不将列表IP错当SOCKS代理。
- 代理出口：支持用户提供的SOCKS5、HTTP CONNECT、HTTPS CONNECT上游，凭据加密保存；不要把上游用户名密码与客户端入口凭据混用。
- 常规使用尽量只需选国家/节点/策略，证书身份与运行参数由系统按可信来源校验；当前开发界面里的手填UID、worker参数不应成为最终日常步骤。公共节点缺乏可信身份依据时明确标记待确认/不可用，不诱导用户猜证书名或关闭验证。
- 各逻辑出口拥有自己的当前节点、固定入口绑定、状态、检测记录和策略。支持手动换节点、同地区重新选择、健康粘性、失败冷却/退避和自动恢复。
- 全部候选不可用时明确断流/失败，不悄悄变成VPS直连，也不擅自跨越用户限定的国家/类型策略。
- 选择了严格住宅策略时，未知或冲突的情报不能假装通过；普通/住宅优先/严格住宅应有可解释的降级边界。
- 旧连接不能跨出口IP无损迁移：健康换线可限时排空旧连接，故障后客户端可能需要重连。入口地址稳定不等于TCP会话永不掉线。

## 5. “使用已有节点连接VPN Gate”的两种含义

A. **复用已有入口**：手机/电脑继续连当前VLESS等入站，由它转交给Miku，再经VPN Gate出站。这是默认主路径。

B. **复用已有出站作前置通道**：VPS通过已有代理/自有节点去连接VPN Gate，形成“客户端 → 入口 → OpenVPN → 前置传输通道 → VPN Gate”的受限链。它和更换最终出口不是同一件事，必须由用户明确选择。TCP-only的HTTP CONNECT不能伪装支持UDP OpenVPN；UDP链路仅在前置协议与核心都支持且通过检测时显示可用。不能导入或授权使用的私有节点不会被擅自使用。

向导会将A/B分开询问，也允许两者都不选。默认直连VPN底层传输并不代表业务可在断线时直连；业务必须仍受所选出口约束。

## 6. 连通性、归属与风险信息

- 分层显示：配置能否解析、端口能否连接、TLS/REALITY握手、OpenVPN握手、隧道DNS、真实业务请求、实际出口IP。
- 分开显示入口VPS IP、上游节点地址、实际出站IP及最近检测时间，不将用户填写国家当作实测所在地，也不把节点自报Ping当作本机测量。
- 国家/地区、ASN、运营商/组织、机房/住宅/移动类型、可用信誉来源、代理/VPN标记；标明信息来源、时间、置信度与互相冲突的结果。
- 对域名显示解析结果、TLS证书/兼容性和解析IP的网络信息。IP地理库结果不等于网站经营者的真实归属地。
- “纯净度”是辅助判断，不承诺100%住宅、独享、匿名、解锁或通过特定网站风控；无可靠数据时显示未知，收费/需要API密钥的数据源作为明确可选项。
- 可选受限速度抽测、历史健康与可达率；并发/频率/流量预算可设，避免把志愿节点反复压测。

## 7. 管理界面与运维

最终页面覆盖：安装/首次向导、概览、入口与客户端、出口工作台、节点库、检测结果与任务、核心与既有服务、域名证书、事件诊断、备份升级与设置。

应能看到实际活动出口、公网IP、入口绑定、健康/保护状态、在线连接、流量口径、故障原因和自动恢复过程；后台任务可取消、查看进度，不能用“已下发命令”假装操作成功。

提供正常停止、开机自启、受控恢复、诊断、日志、完整加密备份、升级前校验/备份、兼容迁移、失败回滚、可保留数据的卸载。发布多个带精确源码/校验文件/平台包/发行说明的Release，不覆盖旧资产。对1核1GB场景提供保守默认预算，不编造容量保证。

## 8. 原始长期规划也不无声删除

原PRODUCT_PLAN中的多机Controller+Agent、跨机器管理、设备身份、可撤销订阅、可选热备与SOCKS5 UDP保留在后续里程碑。它们不阻止先发布可用单机版本，但也不应该被静默从“完整项目”愿景中删掉。

这些项目与当前用户明确加重的3x-ui/sing-box/域名/安装要求需要同时维护版本边界。每次发布说明具体范围；不因代理上游或私有实验通过就宣称整个项目完成。

## 当前用于对齐的默认选择

- 有域名且条件满足：优先受信任HTTPS管理和TLS/Vision入口；REALITY同样可选。
- 无域名：优先提供IP管理地址与REALITY入口方案，而不是强迫域名或永久SSH转发。
- 已有3x-ui：优先保留、确认复用；不默认卸载或替换。用户选择迁移时再执行备份、校验和回滚计划。
- 默认单机保守资源预算、先TCP业务；自动换线先守国家/类型约束，全部失败时停止转发。
- 免费公开节点质量不稳定，显示实测与证据，不营销“永久免费纯净住宅IP”。

以上默认选择可由用户更改；涉及范围分歧时显式更新本对齐稿与交付矩阵，不在实现中悄悄换成更小的目标。
